# 역할 삭제 정책과 V28 적용

`tbl_role.system_role`은 V28에서 제거한다. 엔티티와 목록·상세 DTO도 해당 값을 사용하지 않으며 프론트 그리드의 구분 컬럼과 상세의 기본/사용자 정의 배지를 제거한다. 기존 역할 코드·표시 순서·회원 배정·기능 매핑은 보존한다. 이미 적용한 V11·V27은 변경하지 않고 새 마이그레이션으로 진행한다.

ROOT는 변경할 수 없는 코드로 판단하며 `Role.isRoot()`와 `assertDeletable()`이 삭제를 차단한다. 일반 편집·회원 강등·유일 계정 보호도 유지한다. 프론트는 ROOT 코드에 삭제 버튼을 표시하지 않으며 직접 DELETE 요청을 보내도 서버가 `ROLE_PROTECTED`로 거절한다.

그 외 모든 역할은 다음 사용처가 없으면 삭제할 수 있다. ADMIN·MANAGER도 동일하며 삭제된 행을 다시 만들지 않는다.

- 회원 배정: 탈퇴 회원의 외래키까지 검사해 `ROLE_IN_USE`로 거절한다.
- 접속 허용 설정: 현재 설정의 예외 역할에 있으면 `ROLE_ACCESS_POLICY_IN_USE`로 거절한다. 과거 세션 폐기 기록은 유지하며 삭제를 막지 않는다.
- 회원가입 기본값 USER: 회원이 없는 시점에도 신규 가입에서 참조하므로 `ROLE_DEFAULT_IN_USE`로 거절한다.

삭제 명령은 기존 ROOT 권한 재검증·정책 잠금·`expectedVersion` 검사 후 실행한다. 사용 여부 검사와 삭제·감사 기록은 같은 트랜잭션이며 회원 역할 배정과 접속 정책 변경도 같은 정책 잠금을 사용한다. FK를 끄거나 다른 회원·정책을 자동 변경하지 않는다.

사용자가 삭제를 확인한 뒤 서버가 거절하면 상세를 유지하고 화면 중앙의 안내 팝업에 실제 사용처를 표시한다. 확인 버튼이나 Escape로 안내만 닫으며 저장하지 않은 초안은 보존하고 실패한 DELETE는 자동 재전송하지 않는다.

변경한 MVC와 프론트를 함께 반영하고 MVC 서버를 재시작해 Flyway V28을 적용한다. 실제 권한 삭제는 관리자가 화면에서 선택한 경우에만 수행한다.

검증은 ROOT 삭제·편집 차단, 최초 제공/추가 미사용 역할 삭제, 회원 배정·접속 정책·가입 기본값 차단, 권한·버전 검증, 응답 계약과 임시 MySQL의 V27→V28 데이터 보존 등 12개 테스트를 통과했다. 실제 UI로 사용처별 안내·단일 확인/Escape·초안 보존·정상 삭제와 모바일~4K 팝업 중앙 배치를 확인했다. 새 테스트 소스·검증 화면·임시 DB는 검증 후 제거한다.
