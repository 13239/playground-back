# 관리자 6단계: 사용자 활동 로그·관리자 작업 기록 조회

`/admin/logs`에 두 탭과 읽기 전용 상세 모달을 연결한다. 기존 로그 저장 흐름과 업무 변경 트랜잭션은 그대로 사용한다.

## API와 권한

| GET 경로 | 기능 권한 | 응답 |
| --- | --- | --- |
| `/api/admin/logs/activities` | ACTIVITY_LOG_READ | 로그인·가입 활동 목록 |
| `/api/admin/logs/activities/options` | ACTIVITY_LOG_READ | 활동·결과 필터 코드/문구 |
| `/api/admin/logs/activities/{id}` | ACTIVITY_LOG_READ | 선택한 활동·브라우저·허용된 입력 식별자 |
| `/api/admin/logs/audits` | ADMIN_AUDIT_READ | 저장된 관리자 작업 목록 |
| `/api/admin/logs/audits/options` | ADMIN_AUDIT_READ | 작업·대상 필터 코드/문구 |
| `/api/admin/logs/audits/{id}` | ADMIN_AUDIT_READ | 선택한 작업·변경 전/후·기존 사유 |

두 권한은 각각 `ADMIN_ACCESS`와 함께 검사한다. 필터의 관리자 접근 검사, MVC의 `RequireAdminPermission`, 서비스의 현재 DB 권한 검사와 BFF 인증/요청 서명을 재사용한다. 로그 조회 권한만 있는 계정도 허용된 탭을 사용할 수 있으며 별도의 `USER_READ`를 요구하지 않는다. 수정·삭제·내보내기·되돌리기 API는 추가하지 않았다.

## 검색과 페이지

목록 공통 조건은 `from`, `to`(ISO 날짜), `query`, `page`, `size`다. 활동은 `type`, `result`, 관리 작업은 `action`, `targetType`을 추가한다. 기본 기간은 한국 날짜로 오늘을 포함한 최근 7일이며 종료일의 다음 날 00:00 미만까지 포함한다. 역전된 기간·실제 달력에 없는 날짜·허용되지 않은 크기를 거절한다.

페이지는 1부터 시작하고 표시 개수는 10/20/30/50(기본 10)이다. 같은 검색 조건의 집계와 해당 페이지 행을 반환하며 범위를 넘으면 마지막 페이지로 보정한다. 빈 목록도 1페이지다. 응답은 `items`, `page`, `size`, `totalPages`, `totalElements`다. 발생 시각 내림차순과 ID 내림차순으로 정렬해 같은 시각의 기록도 순서를 고정한다.

검색의 `%`, `_`, `!`는 와일드카드로 해석하지 않는다. 활동은 기록 당시 아이디·닉네임과 현재 공개 회원 정보 및 회원 번호를 함께 검색한다. 따라서 미등록 로그인 실패와 중복 가입 실패도 당시 입력한 식별자로 검색할 수 있다. 관리자 작업의 검색은 작업 관리자 아이디·현재 닉네임·회원 번호를 사용한다.

## 표시와 저장 이력

활동 목록은 공개 회원 식별자·활동·결과·접속 IP·실패 코드의 공개 문구만 읽는다. 상세에서만 브라우저와 기록 당시 입력 아이디·닉네임·로그인 유지 여부를 읽는다. 기록 당시 식별자가 없으면 현재 공개 회원 정보로 보완한다. 아바타는 현재 프로필을 사용한다. 미확인 회원과 시스템 작업은 별도로 표시하고, 사라진 회원도 남은 번호로 식별한다.

관리자 작업은 당시 저장된 `actorRoleCode`를 사용한다. 표시용 역할 이름과 대상의 이름은 현재 사전에서 조회하며 삭제된 항목은 저장된 코드/번호로 표시한다. 변경 전·후 값은 현재 엔티티로 재구성하지 않고 저장된 JSON의 허용 필드에서 읽는다. 역할 이름이 바뀌거나 역할이 삭제되어도 저장된 권한 코드는 보존된다.

JSON 전체를 응답하지 않는다. `AdminLogDetailMapper`가 업무 필드·입력 식별자만 복사하며 비밀번호·토큰·개인정보 원문·임의 키를 전달하지 않는다. 개인정보 조회 감사는 조회한 필드 이름만 표시한다. 기록에 없는 변경 전·후 값을 추정하지 않는다. 저장된 변경 사유는 조회만 하며 개인정보 열람 사유 입력을 다시 추가하지 않았다.

`AdminLogCatalog`는 작업 이름과 필터 옵션을 공유한다. 새로운 작업은 사전에 문구를 추가하고 알 수 없는 과거/미래 작업도 원래 코드로 식별할 수 있다. 신규 스냅샷 필드는 상세 허용 목록에 명시적으로 추가해야 화면에 공개된다.

## 조회 성능과 마이그레이션

Flyway **V18**은 활동 JSON의 아이디·닉네임을 읽는 검색용 가상 컬럼 2개와 활동 결과/종류, 감사 작업/대상 종류 인덱스를 추가한다. 기존 V1~V17과 원본 로그 값은 변경하지 않는다. 기존 INSERT는 새 컬럼을 직접 쓰지 않는다.

목록에서는 원문 JSON을 선택하지 않고 상세 한 건에서만 읽는다. 집계에는 표시용 회원·역할 조인을 넣지 않는다. 대상 이름은 현재 페이지의 식별자만 종류별로 묶어 조회하며 각 행마다 쿼리를 실행하지 않는다. 게임 모드도 페이지에 포함된 게임/모드 코드 쌍만 조회한다. 조회에는 3초 제한을 적용한다. 저장소 장애는 `ADMIN_LOG_UNAVAILABLE` 503, 없는 기록은 `ADMIN_LOG_NOT_FOUND` 404로 구분한다. 성공 응답과 BFF 응답은 no-store다.

## 반영·검증

백엔드를 재시작해 V18을 적용하고 프론트도 함께 반영한다. 새 환경 변수, 관리자 토큰, Redis 서비스는 필요하지 않다. 실제 운영/개발 DB에는 이번 작업에서 마이그레이션을 임의 실행하지 않았다.

격리 MySQL 8.0.37에서 V1~V18·Hibernate 검증·실제 조회·MVC 요청/권한 인터셉터를 검증했다. 브라우저와 BFF는 별도 가상 데이터로 검증했다. 전체 JWT·Redis·배포 서버 연동을 다시 수행한 결과는 아니다. [화면 안내](../../../front/playground/docs/admin-logs-stage6.md)와 [검증 결과·스크린샷](../../../artifacts/admin-development-stage6/verification.md)을 함께 따른다.
