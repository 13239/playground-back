# 게임·장르 관리 개선 4단계: 실제 오목 표시와 운영 상태 연결

관리자가 수정한 게임 이름·한 줄 소개·설명·장르 이름과 순서·모드 이름을 실제 오목 화면에서 사용한다. 실행 코드는 계속 `GOMOKU`, `AI`, `ONLINE`을 사용하므로 표시 이름 변경이 실행 주소나 게임 규칙을 바꾸지 않는다.

## 표시 정보의 경로

관리 쓰기 → MySQL 카탈로그 → 기존 Spring 공개 상세 `GET /api/games/GOMOKU` → Next 공개 상세 BFF `GET /api/games/GOMOKU` → 같은 게임 내 공유 공급자 → 방 목록·생성·대기실·AI 대국·팝업 제목으로 연결한다. 게임·장르 관리와 로비도 같은 카탈로그를 사용한다.

새 BFF 상세 경로는 게임 코드와 응답 코드 일치를 확인하고 공개 여부를 검증한다. 입력 쿼리를 전달하지 않고 요청 취소를 백엔드로 전달한다. 응답에서 관리 버전·이미지 키·내부 필드·실행 URL을 복사하지 않으며 비공개·미지원 모드도 제외한다. 응답과 브라우저 조회 모두 `no-store`를 사용한다.

브라우저 공급자는 게임 화면 내 여러 컴포넌트의 조회를 공유한다. 최초 진입·경로 이동·창 포커스 복귀·문서가 다시 보일 때 읽고, 이전 경로의 요청은 취소한다. 주기 타이머나 새 실시간 스트림은 만들지 않는다. 관리자 저장을 모든 열린 창에 즉시 방송하는 기능은 아니다. 화면으로 돌아오거나 다시 들어올 때 새 값이 반영된다.

서버 `generateMetadata`도 공개 상세에서 현재 이름·소개·AI 모드 이름을 읽는다. `connection()`으로 실제 요청 때 조회하고 React `cache()`는 한 요청 안에서만 공유한다. 조회 실패·숨김 시 고정된 과거 오목 정보로 대체하지 않고 일반 게임 제목을 반환한다. 개인 방 제목·방 코드·회원 정보는 메타데이터에 포함하지 않는다.

## 화면 반영

- 방 목록·생성 배너와 이동 경로에 현재 게임 이름·한 줄 소개를 표시한다.
- 긴 게임 설명은 ‘게임 소개’를 펼쳐 읽고 줄바꿈을 유지한다. 현재 공개된 연결 장르를 이름 라벨로 표시한다.
- AI 시작 버튼·난이도 선택·AI 대국 제목과 온라인 생성 안내·대기실 모드명에 관리 이름을 사용한다.
- 문서 제목과 열린 대국 팝업 제목도 표시 이름을 따른다. 이름 갱신 때문에 팝업을 닫거나 다시 만들지 않는다.
- 사용자 방 제목은 별도 입력이다. 새 방 기본 제목에서 특정 게임의 고정 표시 이름을 제거했다.
- 규칙 설명·보드의 접근성 이름처럼 실제 오목 구현을 설명하는 문구는 게임 표시 이름과 구분해 유지한다.

## 공개·점검·기존 대국

공개 모드를 숨기면 해당 새 실행 버튼을 숨긴다. 공개된 모드의 점검·중지 또는 게임 전체 제한은 안내 문구와 비활성 버튼으로 표시한다. 한 모드의 숨김을 게임 전체 이용 불가로 안내하지 않는다. 조회 실패도 새 실행 가능 상태로 처리하지 않으며 다시 확인할 수 있다.

온라인 이용이 제한돼도 방 목록 조회와 이미 참가한 방의 직접 복귀 링크를 유지한다. 다른 방의 새 입장·초대 코드 입장·새 방 생성은 제한한다. 선택 중인 AI 난이도는 현재 표시 정책에 따라 새 실행을 막는다.

화면의 표시 정책은 실행 권한을 대신하지 않는다. 기존 인증·Origin·브라우저 증명과 Spring의 `GameAvailabilityService`는 그대로 유지한다. 직접 주소 AI 시작·방 생성·신규 입장·준비/시작·재대국에서 기존 서버 검증이 최종 결정한다.

공급자는 공개 데이터 변경·조회 실패 때문에 자식 화면을 바꾸거나 `key`를 변경하지 않는다. 진행 중 AI 워커·돌·방 연결은 유지하고 다음 새 대국·입장은 서버가 다시 확인한다. 실행 중 제한을 이유로 이미 진행한 대국을 강제 종료하지 않는다.

## 검증과 적용

별도 MySQL의 실제 관리 서비스 쓰기와 공개 조회/실행 제한을 6개 시나리오로 검증했다. 공개 상세 BFF·표시 정책·메타데이터 계약은 29건을 확인했다. 실제 화면·AI 워커·보드를 사용한 임시 브라우저 환경에서는 표시 변경·점검/숨김·조회 장애·기존 방 복귀와 돌 보존을 확인했다. 인증과 방 목록 API는 임시 대역이므로 실제 로그인·회원 DB·온라인 양측 대국까지 통합 검증한 것으로 표현하지 않는다.

모바일·태블릿·FHD·QHD·4K 너비에서 긴 게임/모드 이름의 가로 넘침을 확인했다. 5K는 5120×2880 CSS 프레임을 사용했으며 실제 5K 모니터·물리 터치 기기 검증은 아니다.

이번 단계에는 추가 DB 마이그레이션이 없다. 앞 단계 V20/V21과 백엔드 계약이 적용된 상태에서 새 프론트를 반영한다. 실제 실행 중인 서비스·local/dev/prod DB는 변경하거나 재시작하지 않았다. 새 테스트 소스·임시 브라우저 서버·검증용 DB는 검증 후 삭제했다. 자세한 결과는 [검증 기록](../../../artifacts/admin-catalog-integration-stage4/verification.md)에 남겼다.
