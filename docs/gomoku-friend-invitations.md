# 오목 미니 프로필·친구 초대

검증일: 2026-10-28

## 화면 동작

- 대기실 상대의 아바타 또는 닉네임을 누르면 기존 공통 미니 프로필을 연다. 친구 추가·요청 대기·이미 친구인 상태는 기존 친구 기능과 동일하게 처리한다. 본인 프로필은 이 버튼에서 열지 않는다.
- 방을 만든 뒤 빈 대기실의 방장 화면에서 **친구 초대**를 누른다. 친구 검색과 번호 페이지를 제공하며 온라인 친구를 선택할 수 있다.
- 방마다 한 명의 응답을 기다리며 발신자는 대기 중인 초대를 취소할 수 있다. 수신자도 진행 중인 초대 하나만 받는다.
- 수신자의 현재 화면 우측 하단에 발신자·방 제목·규칙·남은 시간·수락/거절을 표시한다. 다른 모달이나 게임 팝업이 열려 있어도 응답할 수 있다.
- 수락이 서버에서 확정된 경우에만 해당 대기실로 이동한다. 다른 오목 방에 참여 중인 사용자는 자동 퇴장시키거나 이동시키지 않는다.
- 초대는 발송 시점부터 15초 동안 유효하다. 같은 요청이나 같은 상대에 대한 중복 발송은 기존 초대를 반환하며 기한을 연장하지 않는다. 기한이 지난 카드는 숨기고 서버가 `REJECTED`로 정리한다.
- 일반 알림 읽음·알림 개수와 짧은 게임 초대를 분리했다.

## 서버 검증과 데이터

- 새 Flyway 마이그레이션 `V30__create_gomoku_friend_invitations.sql`에서 초대 원본과 상태·기한·중복 방지 키를 저장한다.
- 회원 → 방 → 초대 순서로 잠그고, 실제 친구 관계·양방향 차단·방장·현재 로그인/점유 페이지·정원·참가 상태를 검증한다.
- 초대에 당시 방장 참가 세대와 방 revision을 묶는다. 방장 교체·재참가·규칙 변경·정원 변경 등으로 조건이 바뀌면 과거 초대로 입장하지 않는다.
- 비공개 방은 **본인에게 발급된 유효 초대를 수락한 경우에만** 초대를 비밀번호 대신 명시적인 입장 권한으로 사용한다. 기존 일반 입장 API의 비밀번호 검증은 유지하며, 초대 입장도 정원·강퇴·중복 참가·게임 이용 정책을 그대로 검사한다.
- 기존 게임 시계와 Redis 마감 전파를 재사용해 브라우저가 닫혀도 자동 거절한다. 시작/Redis 재구독 때 미처리 초대를 복원하며 평상시 초대 테이블 폴링은 추가하지 않는다. 서버 요청은 기한과 같은 시각부터 수락을 거부하고 만료 상태는 게임 시계 주기에서 확정한다.
- 서버 응답과 DB의 기한은 MySQL `DATETIME(6)` 정밀도로 맞춘다. 클라이언트는 서버 시각과 단조 경과 시간을 사용하며 네트워크 대기 시간도 차감한다.
- 채팅 연결은 Redis 변경 구독을 확정한 뒤 인증 완료·초기 요약을 전달한다. 초기 요약 중 변경 신호 하나를 보관하고 첫 소켓 스냅샷 직후 HTTP 상태를 한 번 복구해 15초 초대가 연결 시작 사이에 누락되지 않게 했다.
- 공개 응답에는 방 코드·비밀번호 해시·내부 회원 번호를 포함하지 않는다.

## API와 적용

- `POST /api/gomoku/invitations/send`: 본인 세션, 방 번호, 현재 pageId, 대상 공개 UUID, 재시도용 requestId.
- `POST /api/gomoku/invitations/accept`, `/reject`, `/cancel`: 본인 세션과 초대 공개 UUID.
- BFF는 동작별 필수 입력만 허용하고 기존 Origin·세션·브라우저 증명 경계를 재사용한다. 서버는 발신자와 기한을 클라이언트 입력에서 받지 않는다.
- 소셜 스냅샷에 `gomokuInvitations`, `serverTime`을 추가했다. 기존 서버의 스냅샷에는 새 필드가 없어도 허용한다.
- 적용 대상은 프론트·백엔드·채팅 서버다. 백엔드 시작 시 Flyway가 V30을 적용한다. 운영 배포와 실제 사용자 DB 변경은 수행하지 않았다.

## 검증

- 별도 임시 MySQL 8.4에서 V1~V30 전체 마이그레이션과 Hibernate 스키마 검증을 통과했다.
- MySQL/JPA 통합 검증 12개: 공개 조회, 중복 요청/대상, 정확한 만료 시각, 서버 자동 거절, 수락/거절·수락/수락 경합, 친구·규칙·권한·접속 조건.
- 입장 보호/시계 검증 8개: 일반 비공개 입장 비밀번호 유지, 유효 초대 입장, 강퇴·중복 방·정원·대국·닫힌 방 보호, 영속 예약 복원 및 유휴 폴링 방지.
- 채팅 검증 5개: Redis 구독 전 인증 응답 방지, 초기 요약 중 변경 신호 보존, 구독 전 취소 정리, 다른 회원 신호 격리, 기존 조회 제한 오류 계약 유지.
- 프론트 계약/BFF/상태 검증 17개: 필드 검증, 내부 필드 제거, 서버 시각 카운트다운, 확정 수락만 이동, 동시 응답 방지, 만료·로그아웃·인증 재확인 경계, 기존 홈 탭 유지, 최초 소켓 스냅샷 복구.
- Chromium·Microsoft Edge에서 원본 대기실·프로필·초대 컴포넌트와 CSS를 사용해 친구 추가, 초대/취소, 수락/거절, 15초 만료, 다른 모달 및 게임 팝업을 확인했다. 320·390·768·1920·2560·3840·5120px 모두 가로 넘침이 없었다.
- Next.js 프로덕션 빌드·TypeScript·변경 파일 ESLint와 두 Java 서버 컴파일을 통과했다.
- 실행한 임시 테스트 소스와 브라우저 검증 화면, 임시 MySQL 컨테이너는 검증 후 제거했다. 기존 테스트와 사용자 데이터는 유지했다.

합계 42개 자동 검증을 통과했다. DB 통합 검증에서 친구/Redis 신호 및 채팅·게임 외부 연결은 모의 객체를 사용했고, 브라우저 검증도 모의 인증·API·WebSocket을 사용했다. 실제 계정으로 전체 시스템을 함께 실행하는 검증과 Firefox·Safari 검증은 수행하지 않았다.
