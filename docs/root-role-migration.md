# ROOT 역할 이름·코드·표시 순서

V27은 기존 `SUPER_ADMIN` 역할을 표시 이름·코드 모두 `ROOT`로 이전한다. 적용된 V11·V12 등 기존 마이그레이션과 과거 감사 기록은 수정하지 않는다.

| 코드 | 표시 이름 | sort_order |
| --- | --- | --- |
| ROOT | ROOT | 0 |
| ADMIN | 관리자 | 1 |
| MANAGER | 매니저 | 2 |
| USER | 유저 | 3 |

권한 관리의 번호 그리드는 `sort_order, code`로 정렬한다. 사용자 정의 역할은 기본값 4로 기본 역할 뒤에 표시하며 같은 순서값에서는 고유 코드로 정렬한다. 기존 역할 선택기는 코드 커서를 유지한다.

기존 최고 관리자 회원의 역할 코드와 기능 매핑은 외래키 검사를 유지한 채 같은 트랜잭션으로 이전한다. 회원의 `role_version`·`management_version`과 역할 버전도 갱신한다. 생성 시각·비밀번호·개인정보·기존 권한 구성·과거 감사 기록은 보존한다. `root_guard` 고유 생성 컬럼과 활성 계정 CHECK, ROOT의 접속 예외 목록 배제 제약을 함께 변경한다. 이전 도중에도 두 코드에 걸쳐 최고 관리자는 최대 한 명이다.

기존 사용자 정의 `ROOT` 코드가 있거나 기존 기본 `SUPER_ADMIN`이 없으면 스키마 변경 전에 중단한다. 해당 데이터를 임의로 덮어쓰거나 최고 관리자로 승격하지 않는다.

MVC·chat 서버를 중지하고 변경한 세 서버를 함께 반영한다. MVC 시작 시 Flyway가 V27을 적용한 뒤 chat을 시작한다. 이전 로그인은 Redis의 `accessRole`에 기존 코드를 보관하므로 기존 최고 관리자 계정은 다시 로그인해 ROOT 세션을 발급받는다. 이전 코드는 접속 제한 예외로 처리하지 않는다.

초기 배정 설정인 `authorization.bootstrap.*`, 초기 배정 클래스·감사 이벤트 코드, API의 `superAdminOnly` 필드와 최고 관리자 판별 메서드 이름은 기존 계약을 유지한다. 이 판별과 실제 배정은 ROOT 코드에만 적용한다.

2026-10-26에 격리한 임시 MySQL에서 기존 V1~V26 후 V27 적용, 최고 관리자 배정/미배정 DB, ROOT 코드 충돌 중단, 이름·정렬·회원·기능 매핑·감사 기록 보존과 외래키·유일 계정·활성 상태 제약을 검증했다. Java 보호 규칙 8개와 MVC/chat Redis 게이트 24개 시나리오도 통과했다. 검증 코드와 임시 컨테이너는 검증 후 삭제한다.
