# 게임·장르 관리 개선 3단계: 입력 정리와 장르 검색 선택

게임 정보의 대표 이미지와 게임·모드·공개 및 이용 상태·장르의 변경 사유 입력을 제거했다. 화면뿐 아니라 게임 요청 DTO·BFF 허용 필드·서비스 처리·응답의 이미지 선택값을 제거했다. 변경 전후 값과 작업자·시각은 기존 감사 기록으로 자동 저장한다.

## 이미지와 변경 사유

- 게임 표지는 프론트가 고정 게임 코드로 연결한다. 오목의 기존 `GomokuCover`를 그대로 사용하며 이름을 변경해도 표지가 달라지지 않는다.
- `thumbnailKey`는 게임 엔티티·생성/수정 요청·관리 및 공개 상세 응답·프론트 공개 계약에서 제거했다. 구현 등록 API의 `thumbnailKeys`와 모듈의 이미지 목록 메서드도 제거했다.
- Flyway V21은 `tbl_game.thumbnail_key`만 제거한다. 게임 이름·소개·설명·장르 연결·노출 순서·공개·이용 상태를 변경하지 않는다. 이미 적용된 V1~V20은 수정하지 않았다.
- 게임 생성/수정·모드 생성/수정·게임 및 모드 이용 상태·장르 생성/수정 요청은 `reason`을 받지 않는다. BFF는 제거한 필드를 보내면 400으로 거절한다.
- 감사 기록의 공통 `reason` 컬럼과 다른 관리자 기능의 사유 입력은 계속 사용하므로 유지한다. 기존 기록의 이미지 키 표시도 과거 이력을 읽는 데 필요해 유지한다. 새 게임 관련 기록에는 사유 대신 null과 변경 전후 스냅샷을 저장한다.

## 장르 검색 선택기

게임 정보의 장르를 검색 가능한 다중 선택 콤보박스로 변경했다. 선택한 장르는 아래에 코드 대신 이름 라벨로 표시하고 × 버튼으로 해제한다. 검색·다음 항목 조회·목록 닫기와 무관하게 선택 집합을 유지한다. 선택/해제한 내용은 게임 정보 저장 시 반영한다.

`GET /api/admin/game-genres/options?query=&cursor=&limit=20`은 다음 형태를 반환한다. 기존 경로를 재사용하고 더 이상 필요하지 않은 옵션의 버전·정렬값·집계 필드는 반환하지 않는다. 공개 장르 API와 관리자 번호 목록 응답은 별도 계약을 유지한다.

```json
{
  "items": [{ "code": "BOARD", "name": "보드", "enabled": true }],
  "nextCursor": null
}
```

선택기는 20개씩 읽고 서버는 1~100개의 limit을 허용한다. 서버 기본값은 기존과 같은 50이다. 검색은 이름·코드로 수행하고 서버의 장르 노출 순서를 따른다. 검색 입력을 200ms 지연하고 이전 검색과 이어 읽기를 취소한다. 다른 검색의 늦은 응답은 현재 결과에 섞지 않는다. 계속 같은 커서를 반환하는 잘못된 응답도 추가 요청으로 반복하지 않는다.

한 게임에는 최대 100개 장르를 연결할 수 있다. 프론트·BFF·서버 DTO가 같은 한도를 사용한다. BFF는 코드 문법·중복·개수와 옵션 응답을 검증한다. 임의의 장르 이름이나 새로운 장르를 게임 저장으로 생성하지 않는다.

사용 중지한 장르는 목록에 상태를 표시하고 새 선택을 막는다. 기존에 연결된 사용 중지 장르는 유지하거나 제거할 수 있다. 한 번 제거한 뒤에는 다시 새로 연결할 수 없으며, 서버도 신규 연결을 `CATALOG_GENRE_DISABLED`/409로 거절한다. 장르 변경과 게임 편집은 기존 권한 정책 잠금으로 직렬화한다. 장르 사용 중지가 게임 전체의 공개·이용 상태를 대신 변경하지는 않는다.

## 키보드·포커스·반응형

입력에 combobox, 검색 결과에 다중 선택 listbox와 option 상태를 제공한다. 포커스는 입력에 두고 활성 옵션은 `aria-activedescendant`로 전달한다. 방향키로 탐색하고 Enter로 선택/해제한다. 마지막 항목에서 아래 방향키를 누르면 다음 항목을 읽는다. 검색 입력의 Enter는 게임 저장을 실행하지 않는다. 한글 조합 중인 키 입력은 조합 동작을 우선한다.

첫 Escape는 선택 목록만 닫고 기존 모달을 유지한다. Tab은 목록을 닫고 다음 입력으로 이동한다. 검색어를 입력한 것만으로 미저장 변경으로 표시하지 않으며 실제 선택/해제는 모달의 미저장 변경 확인에 반영한다.

지원 브라우저에서는 네이티브 popover로 모달 스크롤 영역에 잘리지 않게 표시한다. 선택 라벨 아래 공간이 부족하면 검색창 위에 표시해 열린 목록이 라벨 해제를 가리지 않게 한다. 창·화면 키보드·모달 스크롤·라벨 크기 변경에 따라 위치를 조정한다. popover를 지원하지 않는 경우에는 모달 본문 안에 목록을 표시한다. 기존 1px 보라색 공통 포커스 프레임을 사용한다.

접근성 동작은 [WAI-ARIA 콤보박스](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)와 [다중 선택 목록](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) 문서를 확인했다. 목록 옵션 안에는 중복 체크박스 같은 별도 입력 요소를 넣지 않는다.

## 등록 선택지 정리

`GET /api/admin/game-implementations`는 `code, registered, modes`를 반환한다. 이미 등록한 코드들은 한 번에 조회해 구현 수만큼 개별 조회하지 않는다. 등록 가능한 구현이 없으면 게임 등록 버튼을 숨기고, 새 게임 등록 선택지에서도 이미 등록한 오목을 제외한다. 실제 중복 등록은 기존 서버 검증으로 계속 거절한다.

## 적용과 검증

프론트와 MVC 백엔드를 함께 반영하고 백엔드 시작 시 Flyway V21을 적용한다. 새 API 계약에는 제거한 이미지·사유 필드를 보내지 않는다. 이번 작업은 실제 local/dev/prod DB를 변경하거나 실행 중인 앱을 재시작하지 않았다.

별도 MySQL에서 V1~V21 마이그레이션·스키마·실제 감사 기록·장르 신규 연결 제한·등록 여부·검색 옵션 검증 9건을 통과했다. 실제 BFF와 공개 응답 파서 검증 30건에서 제거한 필드 거절과 다른 관리자 기능의 사유 유지도 확인했다. 실제 컴포넌트와 임시 연결 대역을 사용해 모바일·FHD의 검색·키보드·다중 페이지 선택·라벨 해제·저장 본문·Escape를 확인했다. 실제 기기의 터치·화면 키보드 검증으로 표현하지 않는다.

서버와 프론트 빌드·타입·변경 파일 ESLint 결과와 검증 범위는 [검증 기록](../../../artifacts/admin-catalog-fields-stage3/verification.md)에 남겼다. 새로 작성한 임시 테스트 코드·검증 서버·DB 데이터는 실행 후 삭제했다. 실제 오목 내부의 고정 제목·소개·모드 문구 연결은 후속 단계다.
