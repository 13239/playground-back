# 게임·장르 관리 개선 5단계: 최종 연결·편집 보호 점검

요청한 게임·장르 그리드, 번호 페이지, 행 상세 모달, 순서 변경, 불필요한 입력/API 정리와 실제 오목 연동의 마지막 점검이다. 이번 단계는 프론트의 복귀 갱신·미저장 입력 보호·저장 중 편집 보호를 보완했으며 백엔드 실행 코드나 DB 마이그레이션은 추가하지 않았다.

## 로비와 게임 화면 복귀

게임 목록·장르 목록·게임 상세가 `useCatalogResume`을 공유한다. 창 포커스 복귀·문서가 다시 보일 때·BFCache에서 문서를 복원할 때 현재 공개 데이터를 다시 읽는다. 같은 프레임에 들어온 여러 복귀 이벤트는 리소스별 한 번으로 합치며 주기 타이머는 만들지 않는다.

로비 목록은 첫 페이지부터 다시 읽고 이전 이어 읽기 요청·커서·검색 응답을 분리한다. 이전 요청이 늦게 끝나도 새 검색의 이어 읽기 잠금을 해제하거나 현재 결과에 섞지 않는다. 장르도 같은 방식으로 첫 페이지를 갱신한다. 이미 선택했지만 새 첫 페이지에 아직 나오지 않은 장르를 ‘전체’ 필터로 잘못 표시하지 않는다.

게임 상세는 복귀 전 시작한 느린 요청을 취소하고 현재 값을 새로 읽는다. 공급자 아래의 대국·워커·자식 상태는 그대로 유지한다. 이어 읽기에서 같은 커서를 반복하는 응답은 거절하고 기존 결과를 유지한 채 다시 확인할 수 있게 한다.

## 상세 모달의 미저장 입력

- 게임 정보·플레이 모드·공개 및 이용 상태 탭 전환과 관리 모드/신규 구현 선택 전에 미저장 변경을 확인한다.
- 취소하면 입력과 현재 선택을 유지한다. 확인한 경우에만 초안을 버리고 이동한다.
- 검색어·단순 선택 목록 탐색은 저장 대상 변경으로 취급하지 않는다. 실제 장르 선택/해제는 해당 게임 정보 폼의 변경으로 추적한다.
- 모드 정보와 모드 이용 상태를 함께 수정한 뒤 한쪽만 저장하려 하면 다른 초안이 지워짐을 먼저 확인한다. 취소하면 양쪽 입력을 보존한다. 확인하면 저장 대상 외 폼을 초기화하고 선택한 폼만 저장한다.
- 저장 실패·버전 충돌은 입력과 미저장 상태를 유지한다. 모달 닫기에도 같은 확인을 적용한다.

`CatalogSaveScope`는 상세 모달 안의 저장만 직렬화한다. 한 폼을 저장하는 동안 다른 폼 입력·저장도 잠기고 모달 닫기·탭 전환은 차단한다. 저장 성공 후 상세 재조회 동안에는 이전 버전 폼을 `inert`로 잠가 새 입력이 새 상세 응답에 지워지지 않게 한다. 선택한 탭·모드는 유지한다. 카탈로그 모달 밖의 기존 관리자 저장은 기존 폼별 동작을 유지한다.

공통 확인창의 개발 모드 effect 재구독에서 이전 `close` 이벤트가 다시 열린 확인창을 즉시 닫는 문제도 보완했다. 실제로 닫힌 이벤트만 처리하고 중첩 확인창의 Escape가 바깥 상세를 함께 닫지 않게 한다.

## 요청 사항 완료 범위

1. 게임·장르 관리: 테이블 그리드, 번호 페이지, 행 클릭 상세 모달.
2. 게임·장르 노출 순서: 그리드 순서 변경 모드, 드래그/키보드 이동, 저장·취소, 버전 충돌 보호.
3. 게임 정보: 대표 이미지 선택·수동 순서·변경 사유 제거, 검색 다중 장르 선택과 이름 라벨.
4. 플레이 모드: 수동 순서·변경 사유 제거, 인원 고정 게임의 최소/최대 입력 숨김.
5. 공개·이용 상태와 장르: 변경 사유 제거, 수동 최신 내용 불러오기 버튼 제거.
6. 연결된 계약: 미사용 전용 필드·처리·이미지 DB 컬럼 제거. 다른 관리자 기능이 쓰는 공통 감사 사유와 과거 이력 해석은 유지.
7. 실제 연동: 게임·장르 관리, 로비, 오목의 표시 정보·모드 이름·공개/이용 상태가 같은 카탈로그를 사용. 기존 대국·본인 방 복귀는 유지.
8. 최종 보호: 복귀 갱신, 늦은 응답 분리, 탭/모드 전환·다중 폼 저장·저장 중 입력·재조회·충돌 보호.

## 검증과 적용

이번 단계는 실제 React 컴포넌트·훅·스타일과 임시 API 대역으로 브라우저 38항목을 검증했다. React 개발 모드의 Strict Mode도 켠 상태다. 서버 역할/인증·DB는 대역이므로 운영 로그인이나 실제 회원 DB까지 연결한 통합 검증으로 표현하지 않는다. 실제 MySQL·관리 쓰기·공개 조회/실행 제한 검증은 [4단계 기록](../../../artifacts/admin-catalog-integration-stage4/verification.md), 순서 API와 그리드는 1~2단계 기록에 있다.

이번 변경의 확인창은 320·390·768·1920 너비에서 화면 안에 배치됨을 확인했다. 전체 목록·대국 화면의 FHD/QHD/4K와 5K CSS 프레임 검증은 이전 단계 기록을 함께 따른다. 실제 물리 터치·5K 모니터 검증은 아니다.

적용 시 1~3단계 백엔드 계약과 Flyway V20/V21, 최종 프론트를 함께 반영한다. 이미 V20/V21을 적용했다면 이번 단계의 추가 DB 변경은 없다. 실제 실행 중인 앱·local/dev/prod DB는 변경하거나 재시작하지 않았다. 임시 테스트 소스·API 서버·브라우저 탭은 검증 후 정리했고 기존 테스트·사용자 `.gitignore`·다른 작업 내용은 유지했다. 결과는 [최종 검증 기록](../../../artifacts/admin-catalog-final-stage5/verification.md)에 남겼다.
