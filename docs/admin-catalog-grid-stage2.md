# 게임·장르 관리 개선 2단계: 목록·순서 변경·상세 모달

후속 [3단계](admin-catalog-fields-stage3.md)에서 대표 이미지·변경 사유 제거와 검색형 장르 선택기를 구현했다. 아래 장르 옵션 경로는 유지하며 응답 필드는 3단계 계약을 따른다.

게임·장르 목록을 전체 폭의 행·열 그리드로 변경했다. 이름·코드 검색, 10·20·30·50개 표시, 첫·이전·번호·다음·마지막 페이지, 행 클릭 상세 모달을 제공한다. 공개 여부와 이용 상태는 서로 다른 열로 표시하고 장르는 실제 연결 게임 수를 표시한다.

## 관리자 조회 계약

| 메서드 | 경로 | 응답 |
|---|---|---|
| GET | `/api/admin/games?query=&page=1&size=10` | 게임 목록 요약의 번호 페이지 |
| GET | `/api/admin/game-genres?query=&page=1&size=10` | 연결 게임 수가 포함된 장르 번호 페이지 |
| GET | `/api/admin/games/{code}` | 기존 게임 상세 |
| GET | `/api/admin/game-genres/{code}` | 장르 상세와 연결 게임 수 |
| GET | `/api/admin/game-genres/options?query=&cursor=&limit=50` | 장르 선택기의 기존 커서 응답 |

관리 목록의 기본 페이지는 1, 크기는 10이다. 허용 크기는 10·20·30·50이다. 마지막 페이지를 넘으면 현재 마지막 페이지로 보정하고 빈 목록은 1페이지로 반환한다. 목록 응답은 `items, page, size, totalPages, totalElements, orderVersion`이다. `orderVersion`은 전체 노출 순서 버전이다.

기존 관리자 게임 커서 조회는 번호 페이지로 대체하고 사용하지 않는 관리 서비스 메서드는 제거했다. 장르 선택기에 필요한 커서 조회는 `/options`로 분리했다. 공개 `/api/games`, `/api/game-genres`의 커서 계약은 유지한다. 모든 새 경로는 기존 BFF·로그인·브라우저 증명·관리자 진입 및 GAME_READ 권한 검사를 사용한다.

이름과 코드를 실제로 검색하며 `%`, `_`, `!`는 검색 와일드카드로 실행하지 않는다. 한글 검색은 ASCII 코드 컬럼과 비교하지 않아 문자셋 충돌을 피한다. 게임 목록은 긴 설명을 응답에서 제외하고 현재 페이지의 모드를 일괄 조회한다. 연결 게임 수는 현재 페이지의 장르를 한 번에 집계하며 숨김 게임도 포함한다. 별도 DB 검증에서 장르 페이지 크기를 10개에서 50개로 늘려도 쿼리는 네 번으로 동일했다.

## 순서 변경 모드

GAME_WRITE 권한으로 `순서 변경`을 누르면 검색을 해제하고 전체 노출 순서를 편집한다. 이 모드에서는 행을 눌러 상세가 열리지 않는다. 손잡이의 Pointer Events로 마우스·펜·터치 드래그를 처리하고 위·아래 버튼 및 손잡이의 Alt+위·아래 키로 같은 이동을 수행한다. 페이지를 넘어도 이동한 손잡이로 키보드 포커스를 복귀시킨다.

선택한 행은 이전 페이지의 마지막 위치 또는 다음 페이지의 첫 위치로 이동할 수 있다. 페이지를 이동해도 미저장 초안을 보존한다. `순서 저장` 전에는 서버 순서를 변경하지 않고, 취소하면 기존 순서로 돌아간다. 변경이 있을 때 취소·브라우저 이탈을 확인한다. 서버 충돌 시 초안을 보존하고 추가 이동·저장을 중단하며 취소 후 다시 편집하도록 안내한다.

전체 목록을 읽지 않는다. 방문한 원본 페이지만 캐시하고 이동 구간의 위치 변환으로 현재 페이지가 참조하는 원본 위치를 구한다. 저장 시에는 이동 대상과 최종 위치의 다음 행만 추가 조회하고, 뒤쪽부터 행당 한 번의 이동으로 정리한다. 같은 행을 여러 번 드래그해도 1단계 API의 중복 코드 금지 계약을 지킨다. 한 번에 서로 다른 100개 행까지 이동할 수 있다.

## 상세 모달

행을 선택할 때만 최신 상세를 조회한다. 게임은 기존 정보·플레이 모드·공개 및 이용 상태 탭을 모달 안에서 제공한다. 장르도 목록에서 가져온 값을 그대로 저장하지 않고 상세 버전을 새로 조회한다. 저장 성공 후 목록과 모달을 다시 조회하고 조회·편집·공개 상태 변경의 기존 기능 권한을 유지한다.

게임·장르의 `최신 내용 불러오기` 버튼은 제거했다. 직접 조회 API는 모달 진입·저장 후 갱신에 계속 사용한다. 저장 중에는 모달 닫기를 막고, 미저장 입력을 닫을 때 확인한다. 내부 확인 모달의 Escape가 바깥 상세 모달까지 닫지 않게 처리한다. 닫은 후 선택했던 목록 버튼으로 포커스를 돌려준다.

인원이 고정된 오목은 최소·최대 인원 입력과 지원 인원 안내를 모두 숨긴다. 저장 요청에는 구현에서 고정한 인원을 사용한다. 인원 범위를 지원하는 다른 구현은 기존 입력과 서버 검증을 유지한다.

## 반응형과 적용 범위

목록의 가로 스크롤을 표 안에 제한하고 이름 열을 고정한다. 순서 변경 모드의 손잡이만 터치 스크롤을 막아 그 외 영역의 화면 탐색은 유지한다. 모달은 화면 높이에 맞추고 본문만 스크롤해 닫기 동작을 항상 사용할 수 있게 한다. 기존 공통 1px 포커스와 보라색 테두리를 사용한다.

추가 DB 마이그레이션은 없다. 프론트와 MVC 백엔드를 함께 반영하고 1단계 V20을 적용해야 한다. 이번 작업은 실제 앱을 재시작하거나 실제 local/dev/prod DB를 변경하지 않았다.

대표 이미지·변경 사유 제거와 검색 가능한 장르 콤보박스, 게임 내부 고정 문구 정리는 후속 단계다. 이번 상세 모달은 기존 편집 기능을 이동한 것이며 해당 항목을 완료한 것으로 취급하지 않는다.

## 검증

별도 MySQL의 실제 마이그레이션·스키마·목록·검색·집계·권한·정렬 연계 검증 6건, 실제 BFF 경로·응답 파서 검증 29건을 통과했다. 초안 알고리즘은 무작위 2,000개 시나리오의 240,000회 이동을 일반 배열과 비교해 1,239,404개 조건을 확인했다. 임시 테스트 코드는 검증 후 삭제한다.

실제 컴포넌트에 연결 대역을 주입한 별도 로컬 화면에서 드래그·반복 이동·페이지 간 이동·저장·취소·상세 수정·미저장 확인·내부 Escape·키보드 포커스·충돌 안내를 확인했다. 390·834·1920·2560·3840 너비와 5120 너비 iframe에서 레이아웃을 확인했다. 브라우저의 직접 뷰포트는 최대 4096으로 제한되므로 5K는 독립 iframe의 실제 CSS 뷰포트 5120으로 검증했다. 실제 기기의 터치 입력이나 5K 모니터 실물 검증으로 표현하지 않는다.

프론트 프로덕션 빌드·타입·변경 파일 ESLint와 서버 배포 JAR 빌드를 확인하고 [검증 기록](../../../artifacts/admin-catalog-grid-stage2/verification.md)에 결과를 남긴다.
